    The idea in four timestamps

    A client cannot know how wrong its clock is by looking at it. So it asks the server, and notes four times.

    1. t1: the client sends a request and writes down its own clock.
    2. t2: the server receives it and writes down its clock.
    3. t3: the server sends the reply and writes down its clock.
    4. t4: the client receives the reply and writes down its own clock.

    Round-trip delay

    Total time on the wire, without the time the server spent thinking.

    delay = (t4 − t1) − (t3 − t2)

    Clock offset

    Assume the request and the reply took equally long. Then the offset is the average of the two one-way differences.

    offset = ((t2 − t1) + (t3 − t4)) / 2

    The client adds this offset to its clock and is now close to the server.

    Why congestion hurts

    The equal-delay assumption breaks when one direction waits in a long queue. The leftover error is half the difference between the two directions.

    error = (forward delay − return delay) / 2

    What the client does about it

    It keeps the last 8 samples and trusts the one with the smallest delay, because a short trip is least likely to have been stuck in a queue. This is the same idea as NTP's clock filter.

    What the network does about it

    Ryu watches port counters on the slow link. When it passes 2.5 Mbps, Ryu rewrites the flow rules so sync packets use the fast link. When it drops under 0.8 Mbps, they go back. Sync packets are also marked DSCP EF so the queue can serve them first.
